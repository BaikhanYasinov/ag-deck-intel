# AG Ventures — Deck Intelligence, фаза 0

Локальный инструмент анализа питч-деков. Загружаете `.pdf` или `.pptx`, получаете
оценку по шкале 0–100, вердикт, красные флаги, вопросы фаундеру и одностраничную
инвестиционную справку.

# Уже работает

- Приём `.pdf` и `.pptx`, дедупликация по хешу, лимит 50 МБ
- Растр каждой страницы в 150 dpi и извлечение текстового слоя, OCR для сканов (конфигурируется)
- Классификатор типа документа: инвестдек, бизнес-апдейт, обзор продукта, отчёт
- Три агента фазы 0: команда, проблема и решение, рынок
- Кросс-валидация: ловит утверждения без источника и красные флаги,
  подменяющие «не раскрыто в деке» на «плохо у компании»
- Прогресс по агентам через SSE, отчёт в HTML, экспорт в PDF при наличии Playwright

# Установка

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # впишите ANTHROPIC_API_KEY
python run.py
```

Откройте http://127.0.0.1:8000

### Необязательные зависимости

| Зависимость | Что даёт | Без неё |
|---|---|---|
| LibreOffice (`soffice` в PATH) | Полноценный визуальный анализ `.pptx` | Текст, встроенные картинки и данные диаграмм, в отчёте появляется пометка |
| Tesseract + `pytesseract` | OCR сканированных деков | Страницы без текстового слоя останутся пустыми |
| Playwright (`playwright install chromium`) | Экспорт отчёта в PDF | Печать из браузера |

## Ключевые  решения

**Лимиты длины живут в схеме, а не в вёрстке.** Каждое поле одностраничника
ограничено по символам в Pydantic. Если модель не уложилась, вызов повторяется
с текстом ошибки. Так текст не обрывается посреди слова.

**Одна шкала.** Внутри агенты оценивают по 1–5 с якорями, наружу выходит только
0–100 целыми числами. Параллельных шкал в интерфейсе и отчёте нет.

**«Не раскрыто» отделено от «плохо».** У агента есть поле `not_disclosed`, куда
уходят отсутствующие данные. Отсутствие метрики в деке не превращается в
утверждение о компании.

**Вердикт защищён двумя правилами.** Если документ не инвестдек или покрытие
данных ниже 50%, вердикт по компании не выносится вовсе.

**Инфраструктура за интерфейсами.** SQLite, локальная папка и asyncio-очередь
меняются на Postgres, S3 и Redis без переписывания пайплайна.

## Провайдеры моделей

Все обращения к модели проходят через `app/llm/`. Провайдеров три:

| Провайдер | Что это | Стоимость |
|---|---|---|
| `anthropic` | Облачный API | По токенам |
| `ollama` / `vllm` / `lmstudio` | Локальный OpenAI-совместимый эндпойнт | Бесплатно |
| `transformers` | Модель в процессе приложения | Бесплатно |

Переключение целиком — одна строка в `.env`:

```
LLM_PROVIDER=ollama
LOCAL_MODEL=qwen3-vl:8b
```

Гибрид собирается точечно: роль на своём провайдере.

```
LLM_PROVIDER=anthropic
MODEL_ROLE_CLASSIFIER=ollama:qwen3-vl:4b
MODEL_ROLE_STRUCTURIZER=ollama:qwen3-vl:8b
```

Проверить фактическую маршрутизацию: `GET /api/v1/providers`.

### Режимы работы со зрением

`VISION_MODE=batch` отправляет все нужные страницы одним запросом. Дешевле,
агент видит дек целиком, подходит облачным моделям.

`VISION_MODE=per_page` шлёт страницы по одной, а суждение выносится отдельным
текстовым вызовом поверх собранных наблюдений. Нужен локальным рантаймам, где
многокартиночные запросы поддерживаются не всеми моделями. Работает медленнее,
время растёт линейно по числу страниц.

`VISION_MODE=auto` выбирает режим по провайдеру.

Схема ответа передаётся провайдеру: Ollama и vLLM ограничивают декодирование по
JSON Schema, и ответ валиден по построению. Если рантайм этого не умеет,
происходит откат на режим json_object, а соответствие схеме проверяет Pydantic.

### Контекст Ollama

Окно по умолчанию мало для наших запросов: JSON Schema, текст страницы и
изображение в него не помещаются, промпт молча обрезается, и модель возвращает
невалидный JSON. В логе это выглядит как ошибка разбора, хотя причина в контексте.

В корне проекта лежит `Modelfile`. Соберите свой тег и укажите его в `.env`:

```bash
ollama create qwen3-vl-32k -f Modelfile
```

```
LOCAL_MODEL=qwen3-vl-32k
```

Расширение контекста увеличивает расход видеопамяти. Если карта не тянет,
снижайте `num_ctx` до 16384 и одновременно `RENDER_DPI` до 100.

### Локальный запуск: что учесть

- Видеопамять: модель на 7–8B в квантизации плюс визуальный энкодер — это
  порядка 8–10 ГБ. Две модели одновременно на одну карту не поместятся.
- `LOCAL_CONCURRENCY=1`: параллельные запросы на одной видеокарте только мешают
  друг другу, поэтому провайдер сериализует их семафором.
- `transformers` грузит модель в процесс приложения. Инференс вынесен в
  отдельный поток, иначе он блокирует event loop и роняет SSE-прогресс.
- На CPU vision-модель обрабатывает страницу минутами. Проверка без GPU
  получится нерепрезентативной.

## Ограничения фазы 0

- Работают три агента из семи. Остальные четыре и агент рисков — фаза 1.
- Якоря рубрики написаны только для измерения «Команда». Остальные идут на общем
  описании, из-за чего их оценки будут менее стабильны. Это главный кандидат на
  доработку.
- Блок рыночных бенчмарков и биография фаундера отдают заглушку: веб-поиск
  отключён. Включается флагом `ENRICHMENT_ENABLED` после появления поискового API.
- Провайдер `transformers` написан под интерфейс `AutoModelForImageTextToText`.
  Для моделей с нестандартным препроцессингом потребуется правка `_run`.
